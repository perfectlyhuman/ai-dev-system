# Chapters — domain knowledge (what & where + the WHY of the architecture)

Each chapter is the durable knowledge for ONE domain: what was built, where it lives, how it's shaped, and why the architecture is the way it is. Written for a fresh agent (human or Gilfoyle) with zero context.

**Chapters are NOT where decisions and lessons are stored.** Those have their own single-source-of-truth homes:
- Significant decisions → `../decisions/` (micro-ADRs)
- Known traps → `../lessons/`

A chapter instead carries a short **"Decisions & lessons affecting this domain"** pointer list linking to the relevant files in those dirs. This keeps ONE copy of each decision/lesson — the same copy the cloud agent reads. Use `TEMPLATE.md` to start a new chapter.
